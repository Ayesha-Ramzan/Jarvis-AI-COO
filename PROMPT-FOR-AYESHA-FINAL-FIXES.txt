1. (HIGHEST PRIORITY — a real broken feature) Switching an already-active skill to a newly created
   version is broken. Live repro: create a draft, activate it (200, v1 becomes active), create a
   v2 via POST /{id}/versions (201), then POST /{id}/activate with {"version_id": "<v2 id>"} while
   the skill is still active on v1. Expected: 200, active_version_id becomes v2's id. Actual: 409
   "A disabled skill cannot be reactivated" — even though the skill was never disabled. This is
   documented as supported behavior in the README ("switch active version") and is one of the
   spec's seven minimum required API capabilities ("Activate an approved version"), so it has to
   actually work, not just be described as working.

   Root cause: app/lifecycle.py's TRANSITIONS map only defines ACTIVE -> {DISABLED}. skills.py's
   activate_skill calls can_transition(skill.status, SkillStatus.ACTIVE) unconditionally for the
   non-idempotent path, including when the skill is already ACTIVE and the owner is legitimately
   switching to a different version. Since ACTIVE -> ACTIVE isn't in the map, the call returns
   False and the 409 branch fires — a branch that was only written with the disabled-skill case in
   mind, which is why the error message is wrong too.

   Fix properly: the state-machine transition check should only gate genuine status transitions
   (DRAFT -> ACTIVE, and blocking DISABLED -> ACTIVE). Switching which version is active while the
   skill *stays* ACTIVE is not a status transition and shouldn't be routed through can_transition
   at all — it needs its own explicit path that only checks the skill isn't DISABLED. Then add the
   test that's been missing this whole time: create v1, activate it, create v2, activate v2
   specifically, assert 200 and active_version_id now equals v2's id, and assert v1's version row
   is still untouched. Also verify manually against a running instance (not just the test) and
   paste the real curl output showing 200, since this exact path is what silently broke last time
   despite 49 "passing" tests.
